//=== Huawei

PacketFence supports the S5710/S5720/S5735 switch from Huawei.

==== Global configuration

Global configuration for 802.1X, Mac authentication, accounting and CLI login:

----
undo authentication unified-mode

radius-server template packetfence
 radius-server shared-key cipher <yourSecret>
 radius-server authentication 192.168.1.5 1812
 radius-server accounting 192.168.1.5 1813
 radius-server retransmit 2

# used for RADIUS Disconnect messages
radius-server authorization 192.168.1.5 shared-key cipher <yourSecret>

# to accept RADIUS Disconnect messages with MAC in AA-BB-CC-DD-FF-EE format
radius-server authorization calling-station-id decode-mac-format ascii
 hyphen-split common

aaa
 authentication-scheme pf-auth
  authentication-mode radius
 accounting-scheme pf-acct
  accounting-mode radius
 # for CLI authentication
 service-scheme pf-cli
 domain pf
  authentication-scheme pf-auth
  accounting-scheme pf-acct
  service-scheme pf-cli
  radius-server packetfence

# set default common domain used for authentication
domain pf
# if you want CLI login
# domain pf admin

dot1x enable
mac-authen
dot1x timer reauthenticate-period 10800
mac-authen timer reauthenticate-period 10800
dot1x dhcp-trigger

snmp-agent
snmp-agent local-engineid 800007DB0304F9389D2360
snmp-agent community read cipher <privateKey>
snmp-agent community write cipher <privateKey>
snmp-agent sys-info version v2c v3
----

==== CloudEngine S5735 running YunShan OS (V600)

The CloudEngine models running YunShan OS (V600) use the unified-mode NAC
configuration and are declared in PacketFence as `Huawei::S5735`. That switch
type additionally supports dynamic ACLs: the access list of the role is pushed
inline in the Access-Accept with the `HW-Data-Filter` RADIUS attribute, so no
ACL has to exist on the switch beforehand. Enable `Access list mapping` on the
switch entry to turn it on.

Global configuration:

----
radius local-ip <switch management ip>

radius-server template packetfence
 radius-server shared-key cipher <secret>
 radius-server authentication <packetfence ip> 1812 weight 80
 radius-server accounting <packetfence ip> 1813 weight 80
 radius-server retransmit 3 timeout 5
 undo radius-server user-name domain-included

radius-server authorization <packetfence ip> shared-key cipher <secret>

aaa
 authentication-scheme packetfence
  authentication-mode radius
 accounting-scheme packetfence
  accounting-mode radius
 domain packetfence
  authentication-scheme packetfence
  accounting-scheme packetfence
  radius-server packetfence
----

NOTE: `radius local-ip` is what starts the listener used for
deauthentication. Without it the switch answers ICMP port unreachable on UDP
3799 and every Disconnect-Request from PacketFence times out.

===== Dynamic authorization (CoA / Disconnect)

PacketFence re-evaluates the access of a connected endpoint (role change,
registration, security event) by sending a RADIUS Disconnect-Request to UDP
3799, the endpoint then authenticates again and gets its new VLAN and access
list. Every address allowed to send these requests must be declared with
`radius-server authorization`, with the shared secret of the switch entry in
PacketFence: a request from any other address gets no answer at all. `radius-server session-manage` is not needed for it.

The Disconnect-Request identifies the endpoint by its MAC address
(`Calling-Station-Id`) only. The switch silently ignores a request whose
`Acct-Session-Id` does not match the current session, so none is sent.

In PacketFence, set the *Deauthentication Method* of the switch to `RADIUS`.
When the switch is reached through a PacketFence connector, the requests leave
from the connector: enable *Use Connector For Deauth* on the switch entry and
declare the connector IP in `radius-server authorization` instead.

After an access re-evaluation, the endpoint shows a new `User ID` and
`User access time` in:

----
display access-user mac-address <mac as xxxx-xxxx-xxxx>
----

Access profiles and interface:

----
dot1x-access-profile name packetfence
 dot1x authentication-method eap

mac-access-profile name packetfence

authentication-profile name packetfence
 dot1x-access-profile packetfence
 mac-access-profile packetfence
 authentication dot1x-mac-bypass
 access-domain packetfence force
 authentication mode multi-authen

interface GE1/0/1
 port link-type hybrid
 port hybrid pvid vlan <default vlan>
 port hybrid untagged vlan <every vlan PacketFence may assign>
 authentication-profile packetfence
----

NOTE: the port has to be `hybrid`. On an `access` port the endpoint
authenticates but the VLAN returned by PacketFence is never applied, and every
VLAN PacketFence can return must be listed in `port hybrid untagged vlan`.

===== Dynamic ACL behaviour

The rules PacketFence sends look like `$1 permit tcp dst 192.168.1.10/32 443`,
one per instance of the attribute, and they are evaluated in ascending rule
number, first match wins.

Three behaviours are worth knowing when troubleshooting:

* The switch applies the attribute from the *Access-Accept* only. A CoA-Request
  carrying `HW-Data-Filter` is answered CoA-ACK but the rules are not applied,
  which is why access re-evaluation disconnects the endpoint so it
  authenticates again.
* A rule the switch cannot parse makes it discard *the whole access list*
  silently, leaving the endpoint with unrestricted access. PacketFence
  therefore drops a rule it cannot express rather than sending it.
* There is no implicit deny: an endpoint matching no rule is permitted.
  PacketFence appends a catch-all deny to every access list to keep the
  semantics of the Cisco syntax the access lists are written in.

`display access-user interface <interface> detail` shows
`DACL group name(Effective)` when an access list is installed; the line is
absent when the switch discarded it.

===== Flow export (sFlow)

The switch can export sampled traffic to the Fingerbank collector of
PacketFence (UDP 6343). The S5735R-L has no NetStream (IPFIX / NetFlow)
command, so sFlow is the only flow export available on this model. The global
settings live in the `sflow` view, the sampling is enabled per interface and
per direction, and the rate cannot be lower than 1 packet out of 4096 (8192 by
default):

----
sflow
 sflow agent ip <switch management ip>
 sflow source ip <switch management ip>
 sflow collector 1 ip <collector ip>

interface GE1/0/1
 sflow flow-sampling collector 1 inbound
 sflow flow-sampling collector 1 outbound
 sflow flow-sampling rate 4096 inbound
 sflow flow-sampling rate 4096 outbound
 sflow counter-sampling collector 1
 sflow counter-sampling interval 10
----

`display sflow configuration` lists the collector and, per interface, the
collector, rate and counter interval in use.
