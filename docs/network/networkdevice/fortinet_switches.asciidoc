//=== Fortinet FortiSwitch

This section shows how to configure RADIUS, MAC Authentication, and 802.1X on a
FortiSwitch running FortiSwitchOS 7.x.

CLI access to the FortiSwitch is required for this configuration.

==== RADIUS

Define an IPv4 RADIUS server using the CLI:

 config user radius
   edit <name>
     set addr-mode ipv4
     set server <IPv4_address>
     set source-ip <ipv4_address>
     set radius-port <radius_port_num>
     set secret <server_password>
     set auth-type {auto | chap | ms_chap | ms_chap_v2 | pap}
     set nas-ip <IPv4_address>
     set all-usergroup {enable | disable}
     set link-monitor {enable | disable}
     set link-monitor-interval <5-120 seconds>
   end
 end

==== RADIUS CoA (Disconnect)

PacketFence deauthenticates endpoints with RADIUS Disconnect-Requests sent to
UDP port 3799. Enable CoA on the RADIUS server definition:

 config user radius
   edit <name>
     set radius-coa enable
   next
 end

The CoA port is set globally (3799 by default):

 config system global
   set radius-coa-port 3799
 end

The FortiSwitch also needs `radius-acct` in the `allowaccess` list of the
interface that receives the Disconnect-Request (the management interface, or
`internal` for a FortiLink-managed switch). Without it, the switch silently
drops the request and PacketFence logs a timeout on port 3799:

 config system interface
   edit internal
     set allowaccess ping https ssh radius-acct
   next
 end

When the FortiSwitch is managed by a FortiGate (FortiLink), the RADIUS server
(with `set radius-coa enable`) is defined on the FortiGate and pushed to the
switch, but `allowaccess` on the switch `internal` interface is not. A value set
on the switch CLI is overwritten the next time the FortiGate resynchronizes the
switch (for example after a FortiGate reboot). Push it from the FortiGate with a
custom command instead, so it is applied on every synchronization:

 config switch-controller custom-command
   edit "fsw-coa-allowaccess"
     set command "config system interface %0a edit internal %0a set allowaccess ping https ssh radius-acct %0a next %0a end %0a"
   next
 end

 config switch-controller managed-switch
   edit <switch_serial_number>
     config custom-command
       edit 1
         set command-name "fsw-coa-allowaccess"
       next
     end
   next
 end

The FortiSwitch sends RADIUS from its FortiLink address (for example
169.254.1.2). The FortiGate needs a firewall policy from the `fortilink`
interface to the PacketFence server (RADIUS, with NAT if the FortiLink subnet
is not routed), and a virtual IP that forwards UDP 3799 to the switch for CoA.
Set `nas-ip` on the RADIUS server to the address used as the switch identifier
in PacketFence.

==== Port Security Global Settings

Using the CLI:

 config switch global
   config port-security
     set link-down-auth {no-action | set-unauth}
     set mab-reauth {enable | disable}
     set max-reauth-attempt <0-15>
     set reauth-period <0-1440>
   end

NOTE: Changes to global settings only take effect when new 802.1X/MAB sessions
are created.

==== MAB

FortiSwitchOS 7.2.3+ supports MAB-only authentication. In this mode, the
FortiSwitch performs MAB authentication without EAP authentication. EAP packets
are not sent. Enable MAB-only authentication:

===== Switch Interface Configuration

 config switch interface
   edit interface_name
     config port-security
       set port-security-mode {802.1X | 802.1X-mac-based}
       set mac-auth-bypass enable
       set auth-order MAB
     end
   next
 end

==== 802.1X

FortiSwitchOS 7.0+ supports 802.1X client mobility between ports without
deleting the 802.1X session. For example, an 802.1X client PC connected through
an IP phone to port1 can move to a third-party switch connected to port2 without
session deletion.

This feature is available for 802.1X port-based authentication, 802.1X MAC-based
authentication, MAB enabled or disabled, and EAP pass-through mode enabled or
disabled.

===== Switch Interface Configuration

Configure 802.1X settings on an interface:

Using the CLI (for FSR-124D, 200 Series, FS-4xxE, 500 Series, FS-1024D,
FS-1024E, FS-T1024E, FS-1048E, and FS-3032E):

 config switch interface
   edit <port>
     config port-security
       set allow-mac-move-to {disable | enable}
       set eap-egress-tagged {disable | enable}
       set port-security-mode {none | 802.1X | 802.1X-mac-based}
         set framevid-apply {disable | enable}
         set auth-fail-vlan {enable | disable}
         set auth-fail-vlanid <vlanid>
         set auth-priority {MAB-dot1x | dot1x-MAB | legacy}
         set authserver-timeout-period <3-15>
         set authserver-timeout-vlan {enable | disable}
         set authserver-timeout-vlanid <1-4094>
         set eap-passthru {enable | disable}
         set guest-auth-delay <integer>
         set guest-vlan {enable | disable}
         set guest-vlanid <vlanid>
         set mac-auth-bypass {enable | disable}
         set open-auth {enable | disable}
         set radius-timeout-overwrite {enable | disable}
       end
       set security-groups <security-group-name>
     end

Using the CLI (for FS-124F, FS-124F-POE, FS-124F-FPOE, FS-148F, FS-148F-POE, and
FS-148F-FPOE):

 config switch global
   config port-security
    set allow-mac-move {disable | enable}
   end
 end

 config switch interface
   edit <port>
     config port-security
       set eap-egress-tagged {disable | enable}
       set port-security-mode {none | 802.1X | 802.1X-mac-based}
         set framevid-apply {disable | enable}
         set auth-fail-vlan {enable | disable}
         set auth-fail-vlanid <vlanid>
         set auth-priority {MAB-dot1x | dot1x-MAB | legacy}
         set authserver-timeout-period <3-15>
         set authserver-timeout-vlan {enable | disable}
         set authserver-timeout-vlanid <1-4094>
         set eap-passthru {enable | disable}
         set guest-auth-delay <integer>
         set guest-vlan {enable | disable}
         set guest-vlanid <vlanid>
         set mac-auth-bypass {enable | disable}
         set open-auth {enable | disable}
         set radius-timeout-overwrite {enable | disable}
       end
       set security-groups <security-group-name>
     end

==== Dynamic ACL

FortiSwitchOS 7.x supports Dynamic Access Control Lists (DACL) which allow
PacketFence to push ACL rules to the switch via RADIUS during authentication.

===== RADIUS Server and Security Group

First, ensure a RADIUS server is configured and associated with a security group:

 config user radius
   edit "<radius_server_name>"
     set auth-type ms_chap_v2
     set nas-ip <switch_ip_address>
     set secret <shared_secret>
     set server <packetfence_ip_address>
   next
 end

 config user group
   edit "RadiusGroup1"
     set member "<radius_server_name>"
   next
 end

===== Switch Interface Configuration

Enable DACL on the interface:

 config switch interface
   edit <port>
     config port-security
       set dacl enable
       set port-security-mode {802.1X | 802.1X-mac-based}
       set mac-auth-bypass enable
     end
   next
 end

Complete example with all recommended settings:

 config switch interface
   edit "port2"
     set security-groups "RadiusGroup1"
     set snmp-index 2
     config port-security
       set allow-mac-move enable
       set auth-fail-vlan disable
       set auth-order MAB-dot1x
       set auth-priority legacy
       set authserver-timeout-period 3
       set authserver-timeout-tagged disable
       set authserver-timeout-vlan disable
       set client-limit 20
       set dacl enable
       set eap-auto-untagged-vlans enable
       set eap-egress-tagged enable
       set eap-passthru enable
       set framevid-apply enable
       set guest-auth-delay 5
       set guest-vlan disable
       set mab-eapol-request 3
       set mac-auth-bypass enable
       set open-auth disable
       set port-security-mode 802.1X-mac-based
       set quarantine-vlan enable
       set radius-timeout-overwrite disable
       set auth-fail-vlanid 200
       set authserver-timeout-vlanid 300
       set guest-vlanid 100
     end
   next
 end

===== PacketFence Configuration

On the PacketFence side, configure the switch to use ACL-based enforcement:

1. Navigate to Configuration → Policies and Access Control → Switches
2. Edit your FortiSwitch configuration
3. In the Roles section, enable "Role by Access List"
4. Define the ACL rules on each role, in Configuration → Policies and Access
Control → Roles

ACLs defined on the role use the generic PacketFence syntax, and PacketFence
translates them to the FortiSwitch `NAS-Filter-Rule` format. Example ACL for a
registration role (allows access to the captive portal):

 permit udp any any eq 53
 permit udp any any eq 67
 permit tcp any host 192.168.1.5 eq 80
 permit tcp any host 192.168.1.5 eq 443
 deny ip any any

is sent to the switch as:

 permit in udp from any to any 53
 permit in udp from any to any 67
 permit in tcp from any to 192.168.1.5/32 80
 permit in tcp from any to 192.168.1.5/32 443
 deny in ip from any to any

NOTE: Replace 192.168.1.5 with your PacketFence server IP address.

NOTE: An access list entered for a role in the Roles section of the switch
configuration overrides the role ACL and is sent to the switch as is. It must
already use the FortiSwitch format shown above.

Limitations:

* FortiSwitchOS accepts one rule per `NAS-Filter-Rule` attribute, of at most 80
  characters. PacketFence sends each rule in its own attribute. If a FortiSwitch
  shows `DACL total items :0:` and its event log (`execute log display`) shows
  `NAS-Filter-Rule exceed maximum size 80, failure with batch install`, the
  rules were packed into a single attribute; upgrade PacketFence.
* ICMP rules (`icmp` or protocol `1`) are installed but not enforced by
  FortiSwitchOS 7.x. Use `ip`, `tcp` or `udp` rules.
* With FortiLink, the FortiGate 802.1X security policy may not have a `dacl`
  option (FortiOS 6.2). Enable `dacl` on the switch port, or push it with a
  custom command as described in the RADIUS CoA section.

When DACL is enabled, the switch diagnostic output will show:

 Dynamic Access Control List : Enable

===== Viewing Dynamic ACLs on a Port

Show the dynamic ACLs (DACL) applied to a port using the CLI:

 diagnose switch 802-1x status-dacl <port>

For example:

 diagnose switch 802-1x status-dacl port2

===== Clearing Authorized Sessions

Clear authorized sessions for an interface:

 execute 802-1x clear interface {internal | <port_name>}

Example:

 execute 802-1x clear interface port3

Clear an authorized session by MAC address:

 execute 802-1x clear mac <MAC_address>

Example:

 execute 802-1x clear mac 00:21:cc:d2:76:72
