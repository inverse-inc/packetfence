//=== Juniper

PacketFence supports Juniper switches in MAC Authentication (Juniper's MAC
RADIUS) mode and 802.1X.
PacketFence supports VoIP on the EX2200 (JUNOS 12.6) and EX4200 (JUNOS 13.2)

==== Junos Modules

Standard switch module supporting legacy Juniper switches using Junos versions
before v12.x.

===== Junos v12.x and Junos v13.x

Junos v12.x and v13.x modules designed for switches operating on JuniperOS v12.x
and v13.x. Inherits all functionalities from "EX2200 and EX4200" modules; all
configurations below apply to Junos v12.x and v13.x.

===== Junos v15.x and Junos v18.x

Junos v15.x and v18.x modules designed for switches using JuniperOS v15.x and
v18.x. Inherits all functionalities from "EX2200_v15 and EX2300" modules.

===== Dynamic ACL (Juniper-Switching-Filter)

The Junos v18.x module can push the ACLs of a role in the RADIUS Access-Accept
using the `Juniper-Switching-Filter` attribute (Juniper VSA 48). No filter has
to be created on the switch. It was verified on an EX4400 running Junos 23.4 and
is not available with the older Junos modules. To use it:

* In _Configuration -> Policies and Access Control -> Switches_, edit your
  Juniper switch entry, set the type to `Junos v18.x` and enable *Role by access
  list*.
* Define the ACL for each role under _Configuration -> Policies and Access
  Control -> Roles_, in the Cisco syntax used by the other modules, for example:

  deny tcp any host 192.168.1.5 eq 22
  deny ip any 10.0.0.0 0.0.0.255
  permit ip any any

PacketFence sends one attribute per ACL line:

  Juniper-Switching-Filter = "Match Ip-protocol 6, Destination-ip 192.168.1.5, Destination-port 22 Action deny"
  Juniper-Switching-Filter = "Match Destination-ip 10.0.0.0/24 Action deny"
  Juniper-Switching-Filter = "Match Destination-ip 0.0.0.0/0 Action allow"

IMPORTANT: The switch drops the traffic that matches no line, *ARP included*,
unlike a Cisco ACL whose implicit deny does not apply to ARP. A role that only
lists what it permits leaves the endpoint unable to resolve its gateway, so it
cannot reach even the destinations it permits. Write the ACL as the traffic to
block followed by `permit ip any any`, which lets ARP through.

Ports can be given as numbers or as Cisco port names (`www`, `domain`,
`bootps`, ...), which are sent as their numbers.

The attribute filters the traffic sent by the endpoint and only matches on the
IP protocol, the destination address and the source and destination ports. An
ACL line that cannot be represented is not sent, and a warning is logged in
`packetfence.log`:

* a source address other than `any`,
* `out|` ACLs,
* port operators other than `eq`,
* TCP flags (`established`, `syn`, ...) and ICMP types,
* the `dscp`, `precedence`, `tos`, `fragments`, `time-range` and `option` qualifiers,
* non contiguous destination masks.

Skipping a `permit` only narrows the role. Skipping a `deny` would let the lines
after it allow what it blocks, so the list is cut at that `deny` and ends with
`Match Destination-ip 0.0.0.0/0 Action deny`. Since that also drops ARP, an
endpoint whose ACL was cut this way loses its network access: check
`packetfence.log` for the warning naming the line.

A role whose lines were all skipped gets that deny all as well, and so do ACLs
PacketFence cannot parse: sending no filter would leave the endpoint
unrestricted.

The switch silently ignores a filter over 20 match conditions or 4000
characters, and one attribute holds at most 247 characters. PacketFence cuts
the list at the limit and ends it with the same deny all, with the same effect. On EX2300 and EX3400,
filters of more than one line need Junos 15.1X53-D55 or later.

A refused attribute makes the switch refuse the whole Access-Accept: the
supplicant stays in the `Held` state and `show log messages | match DOT1XD`
shows `DOT1XD_ATTRIBUTE_VALIDATION_FAILED`. `show dot1x firewall` shows the
filter installed for each supplicant.

==== Dynamic authorization (CoA / Disconnect)

The switch listens for Disconnect and CoA requests on UDP 3799 by default and
uses the secret of the `radius-server`, so nothing more has to be configured.
On the EX4400, the `set access radius-disconnect-port` and
`set access radius-disconnect` statements are ignored ("statement ignored:
unsupported platform"). To check the listener:

  show system connections | match 3799

In PacketFence, set the *Deauthentication Method* of the switch to `RADIUS`.

==== Flow export (sFlow)

The switch can export sampled traffic to the Fingerbank collector of
PacketFence (UDP 6343). Enable sFlow on every access port and on the uplink:

  set protocols sflow sample-rate ingress 500
  set protocols sflow sample-rate egress 500
  set protocols sflow polling-interval 10
  set protocols sflow source-ip 192.168.1.2
  set protocols sflow agent-id 192.168.1.2
  set protocols sflow collector 192.168.1.5 udp-port 6343
  set protocols sflow interfaces ge-0/0/1.0
  set protocols sflow interfaces ge-0/0/47.0
  commit

Here 192.168.1.2 is the switch management IP. The collector sample counter
increases in `show sflow collector`, and `show sflow interface` lists the
interfaces as Enabled.

Use sFlow rather than IPFIX on the EX series. Inline IPFIX (inline-jflow)
only samples through a `family inet` firewall filter with `then sample`:
`family ethernet-switching` filters have no sample action and there is no
Layer 2 template, so traffic that the switch only bridges is never exported.
IPFIX would only see traffic routed by an irb interface of the switch (tested
on EX4400, Junos 23.4R2).

        advertisement-interval 5;

    }

        interface access-ports {

        }

        interface access-ports {
            vlan voice;
            forwarding-class voice;
        }
    }
   }
}

    voice {
        vlan-id 3;
    }
}

==== Configuration for MAC authentication floating devices

To support floating devices on a Juniper switch you need to configure the
'flap-on-disconnect' option on each interface individually and remove it from
the access-ports group.

----
# load replace terminal
[Type ^D at a new line to end input]
protocols {
    dot1x {
        authenticator {
            authentication-profile-name packetfence;
            interface {
                ge-0/0/1.0 {
                    mac-radius{
                        flap-on-disconnect;
                    }
                }
                 ge-0/0/2.0 {
                    mac-radius{
                        flap-on-disconnect;
                    }
                }
                .....

                access-ports {
                    supplicant multiple;
                    mac-radius {
                        restrict; 
                    }
                }
            }
        }
    }
}
Ctrl-D
# commit comment "configured for floating devices"
----

NOTE: `flap-on-disconnect` option takes effect only
when the `restrict` option is also set.
