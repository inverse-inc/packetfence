//== Firewall SSO Integration

PacketFence updates firewalls based on device information like IP address and
connected username. Integration guides below show firewall configuration with
PacketFence. PacketFence uses DHCP traffic by default to trigger firewall
updates, but RADIUS accounting traffic is also supported.

To configure firewall updates, go to _Configuration -> System Configuration ->
Main Configuration -> Advanced_:

[options="compact"]
* Trigger Single-Sign-On on accounting.
* Trigger Single-Sign-On on DHCP

Using both methods simultaneously creates duplicate SSO requests when receiving
DHCP and accounting for the same device, potentially overloading your
firewall.

=== VPN users

A VPN session has no MAC address: the VPN puts the address of the remote
client in the Calling-Station-Id of its accounting (FortiGate SSL-VPN for
instance). PacketFence recognizes the accounting of a VPN session by its
User-Name, the address of its tunnel (Framed-IP-Address) and its Connect-Info
starting with `vpn` (FortiGate `vpn-ssl`, `vpn-ipsec`) or its `Virtual`
NAS-Port-Type, and sends the firewall SSO of the user with the address of its
tunnel when:

[options="compact"]
* the VPN authorizes its users through PacketFence: the role given to the user
  at authorization is the role sent to the firewall, so the user name of the
  accounting must be the one of the authorization. Without a known role,
  PacketFence logs it and sends nothing.
* the firewall has *SSO on accounting* enabled. The roles and networks of the
  firewall filter the VPN users like the other devices.

The firewall SSO of a VPN user carries its user name where the MAC address of
a device usually is (the `mac` field of the firewall templates, for the
firewall types that send it), since the session has no MAC address.

The SSO is sent with a timeout of one hour. Configure the VPN to send interim
updates (for instance `set acct-interim-interval` on the RADIUS server of a
FortiGate) so that firewalls which expire the user mapping keep it during
longer sessions.

=== Troubleshooting SSO Integration

For SSO integration issues, verify firewall API connectivity and check
integration logs as described in <<#_log_files,Log Files>> and
<<#_network_connectivity_issues,Network Connectivity Issues>> in the
Troubleshooting section.
