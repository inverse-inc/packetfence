//== Automation of upgrades

Upgrade automation available since PacketFence 11.0 for **same-OS upgrades**.

Please, check if there is a "Specific Automation Upgrade" defined between the current version to the chosen version, it may contain specific steps like changing the OS, updating database version, etc.

[options="compact"]
* Automation may contain **pre-upgrade steps** defined in the following document.
* Perform automated upgrades on **standalone** servers only. Cluster
  upgrades must use the procedure described in the
  <<PacketFence_Clustering_Guide.asciidoc#_performing_an_upgrade_on_a_cluster,Clustering Guide>>
[options="compact"]
* Check "Specific Automation Upgrade" (or "Specific Upgrade") in Upgrading to the needed PacketFence version.
* An exportable backup of the configuration is performed before upgrading

=== Full upgrade

Run following script to perform a full upgrade:

[source,bash]
----
/usr/local/pf/addons/upgrade/do-upgrade.sh
----

The whole output of the upgrade is also written to
[filename]`/usr/local/pf/logs/upgrade/pf-upgrade-<date>_<time>.log` (the
script prints the path when it starts). Attach this file to any support
request about a failed upgrade.

When the package manager ships a new version of a configuration file you
modified (`.rpmnew` on RHEL, `.dpkg-dist` on Debian), the upgrade applies your
changes to the new version. Your previous file is kept as
[filename]`<file>.upgrade-backup`. If your changes can't be applied, your file
is kept as it is and the new version is saved as [filename]`<file>.upgrade-new`
for you to review after the upgrade.
