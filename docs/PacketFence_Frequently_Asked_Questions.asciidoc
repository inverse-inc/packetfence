== Introduction

PacketFence is a fully supported, trusted, Free and Open Source network access
control (NAC) system. As with any complex network infrastructure component,
administrators encounter various challenges during installation, configuration,
and daily operations. This FAQ addresses the most common issues reported by
the PacketFence community, providing practical solutions and troubleshooting
guidance.

The questions and answers in this guide are organized by topic to help you
quickly locate information relevant to your specific deployment scenario.

== Version-Specific Issues

*Problem:* After upgrading to PacketFence 14.0, RADIUS audit logs show no
entries despite active authentication attempts.

*Solution:*

*Database timestamp fix:*
----
ALTER TABLE radius_audit_log MODIFY created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP
----

*Redis cache clearing:*
----
redis-cli -p 6379
FLUSHALL
exit

redis-cli -p 6380
FLUSHALL
exit

/usr/local/pf/bin/pfcmd service pf restart
----

[[ad-nt-error-codes-v14]]
==== Active Directory authentication fails with NT error codes

*Problem:* Authentication against Active Directory fails with specific NT
error codes after upgrading to v14.x.

*Common Error Codes:*

*NT Error 3221225762* ("Syntactically invalid computer name")::
Verify Active Directory FQDN configuration in domain settings. Ensure hostname
format matches AD requirements.

*NT Error 3221225506* ("Access denied")::
The account used for domain join lacks sufficient permissions to create machine
objects in Active Directory.

*Solution:*

. *For FQDN errors:* Check System Configuration → Domain Settings → DNS Name
. *For access errors:* Use account with "Create Computer Objects" permission
. *Verify domain join status:* Test with `wbinfo -t`
. *Check connectivity:* Ensure ports 389, 636, 88, 135 are accessible

*Community Reference:*
https://sourceforge.net/p/packetfence/mailman/packetfence-users/[PacketFence Users Mailing List]

== Certificate & SSL/TLS Management

=== SSL Certificate Management

[[radius-certificate-renewal]]
==== RADIUS SSL certificate renewal

*Problem:* RADIUS SSL certificate is expiring and needs renewal without
service interruption.

*Solution:*

*Step-by-step renewal process:*

. *Navigate to PacketFence directory:*
+
----
cd /usr/local/pf
----

. *Backup existing certificate:*
+
----
cp conf/ssl/server.crt conf/ssl/server.crt.bak
cp conf/ssl/server.key conf/ssl/server.key.bak
----

. *Generate new certificate:*
+
----
make conf/ssl/server.crt
----

. *Restart RADIUS service:*
+
----
/usr/local/pf/bin/pfcmd service radiusd restart
----

. *Verify certificate:*
+
----
openssl x509 -in conf/ssl/server.crt -text -noout | grep "Not After"
----

*Community Reference:*
https://sourceforge.net/p/packetfence/mailman/packetfence-users/[PacketFence Users Mailing List]

[[eap-tls-host-prefix]]
==== Windows machines add "host/" prefix during EAP-TLS

*Problem:* Windows computers prepend "host/" to machine names during
certificate-based authentication, causing authentication failures.

*Solution:*

*This is normal Windows behavior.* Configure authentication source properly:

*Authentication Source Configuration:*

. *Machine Account Search:* Use `servicePrincipalName` attribute
. *Username Attribute:* Set to handle "host/computername" format
. *Advanced Rules:* Create separate rules for users vs machines
. *Certificate Mapping:* Use `userPrincipalName` for computer objects if needed

*Example Configuration:*
----
# In authentication source settings
Username Attribute: servicePrincipalName
Search Filter: (&(objectClass=computer)(servicePrincipalName=host/*))
----

*Community Reference:*
https://sourceforge.net/p/packetfence/mailman/packetfence-users/[PacketFence Users Mailing List]

[[username-attribute-config]]
==== Username attribute configuration issues

*Problem:* Users cannot authenticate, or authentication works inconsistently
with different username formats.

*Solution:*

*Choose appropriate username attributes:*

*sAMAccountName (Traditional):*
* Format: `username`
* Use for: Standard domain authentication
* Best for: Windows environments

*userPrincipalName (Modern):*
* Format: `username@domain.com`
* Use for: Mixed environments, computer accounts
* Best for: Modern Active Directory setups

*Configuration Examples:*

*For User Authentication:*
----
Username Attribute: sAMAccountName
Search Filter: (&(objectClass=user)(sAMAccountName=%u))
----

*For Computer Authentication:*
----
Username Attribute: userPrincipalName
Search Filter: (&(objectClass=computer)(userPrincipalName=%u))
----

*Mixed Environment Setup:*
----
# Create two authentication sources:
# Source 1: Users with sAMAccountName
# Source 2: Computers with userPrincipalName
# Bind both to same connection profile
----

https://sourceforge.net/p/packetfence/mailman/packetfence-users/[PacketFence Users Mailing List]

*Problem:* CX switches successfully authenticate users but Change of
Authorization (CoA) and SNMP functions don't work properly.

*Solution:*

*This is a known limitation with CX switches:*

*What Works:*
* Initial 802.1X authentication
* User role assignment
* Basic RADIUS communication

*What Doesn't Work:*

* SNMP integration for port management
* Automatic VLAN switching

*Workarounds:*

. *Manual Port Resets:* Physical disconnection/reconnection required
. *Use AOS-S Switches:* For full PacketFence compatibility
. *Hybrid Approach:* CX for core, AOS-S for access where CoA is needed

*Alternative Solutions:*
----
# Force reauthentication via switch CLI
switch# aaa authentication port-access interface 1/1/1 client-limit 1
switch# aaa authentication port-access interface 1/1/1 reauth
----

https://sourceforge.net/p/packetfence/mailman/packetfence-users/[PacketFence Users Mailing List]

[[eap-session-mismatch-cluster]]
==== EAP session mismatches in cluster environments

*Problem:* 802.1X authentication fails in clustered PacketFence deployments
when RADIUS requests hit different cluster nodes during EAP conversation.

*Solution:*

*Root Cause:* EAP authentication requires session consistency. When RADIUS
requests are load-balanced to different cluster nodes, EAP state is lost.

*Primary Solution - VIP Configuration:*

. *Configure Cluster VIP for RADIUS:*
+
----
# Switches should send RADIUS requests to cluster VIP, not individual nodes
# Example switch configuration:
radius-server host 10.0.0.100 auth-port 1812 acct-port 1813 key shared-secret

# Where 10.0.0.100 is the cluster VIP address
----

. *Verify VIP Configuration:*
+
----
# Check cluster VIP status:
/usr/local/pf/bin/cluster/node

# Verify RADIUS service binds to VIP:
netstat -ulnp | grep :1812
----

*Alternative Solution - Session Stickiness:*

If VIP isn't possible, configure session persistence based on calling station ID:

----
# Load balancer configuration (if using external LB):
# Hash based on source IP + calling station ID
# Ensures same MAC address always hits same node
----

*Verification Commands:*
----
# Test RADIUS to VIP:
radtest username password cluster-vip:1812 0 shared-secret

# Monitor EAP sessions:
raddebug -t 30

# Check cluster synchronization:
/usr/local/pf/bin/pfcmd configreload hard
----

*Community Reference:*
https://sourceforge.net/p/packetfence/mailman/packetfence-users/[PacketFence Users Mailing List]

*Problem:* Captive portal fails to load when using tagged VLANs for device

+

# Monitor VLAN traffic on PacketFence interface:

tcpdump -i eth0.102 port 80

----
# Switch port must be configured as trunk:
interface GigabitEthernet1/0/1

 switchport trunk allowed vlan 102
 spanning-tree portfast trunk

----
# Configuration → System Configuration → Network Configuration → Interfaces
# Ensure interface has:
# - Correct VLAN ID (102)
# - Proper IP addressing (192.168.102.1/24)
# - Registration role enabled

[[fingerbank-collector-cpu]]
==== Fingerbank collector causes high CPU usage

*Problem:* The fingerbank-collector service consumes excessive CPU resources,
impacting overall system performance.

*Solution:*

*Primary Solution - Disable TCP Handler:*
----
# Create systemd override configuration:
mkdir -p /etc/systemd/system/fingerbank-collector.service.d/

cat > /etc/systemd/system/fingerbank-collector.service.d/override.conf << EOF
[Service]
Environment=COLLECTOR_DISABLE_TCP_HANDLER=true
EOF

# Apply changes:
systemctl daemon-reload
systemctl restart fingerbank-collector

# Verify service is running with new configuration:
systemctl status fingerbank-collector
----

*Alternative Configuration Options:*
----
# Additional environment variables for tuning:
[Service]
Environment=COLLECTOR_DISABLE_TCP_HANDLER=true
Environment=COLLECTOR_DISABLE_UDP_HANDLER=false
Environment=COLLECTOR_WORKERS=2

# Reduce collection frequency:
Environment=COLLECTOR_INTERVAL=300
----

*Impact Assessment:*
* *What you lose:* Advanced TCP-based device fingerprinting
* *What you keep:* DHCP-based device identification, basic fingerprinting
* *Performance gain:* 60-80% CPU reduction typical

*Monitoring Results:*
----
# Before and after CPU monitoring:
top -p $(pgrep fingerbank-collector)

# Check fingerprinting still works:
tail -f /usr/local/pf/logs/fingerbank.log
----

https://sourceforge.net/p/packetfence/mailman/packetfence-users/[PacketFence Users Mailing List]

== Advanced Troubleshooting

=== System Configuration Issues

[[user-database-conflicts]]
==== User management shows "account already exists" errors

*Problem:* Cannot create, modify, or delete users in PacketFence web interface,
getting "account already exists" errors even for new users.

*Solution:*

*Database Consistency Check:*
----
# Check if user exists in database:
mysql -u root -p pf -e "SELECT * FROM person WHERE pid = 'username';"

# Check for orphaned records:
mysql -u root -p pf -e "SELECT p.pid, n.mac FROM person p LEFT JOIN node n ON p.pid = n.pid WHERE p.pid = 'username';"
----

*Browser Session Issues:*
----
# Try accessing in private/incognito mode to bypass cache
# Clear browser cache and cookies for PacketFence domain
# Test with different browser
----

*Service Verification:*
----
# Ensure all PacketFence services are running:
/usr/local/pf/bin/pfcmd service pf status

# Restart web services if needed:
/usr/local/pf/bin/pfcmd service httpd.admin restart
/usr/local/pf/bin/pfcmd service httpd.portal restart
----

*Database Cleanup (if needed):*
----
# Remove orphaned user record (CAUTION: backup first):
mysql -u root -p pf -e "DELETE FROM person WHERE pid = 'problematic-username';"

# Check for related records that might need cleanup:
mysql -u root -p pf -e "SELECT * FROM person_role WHERE pid = 'username';"
mysql -u root -p pf -e "SELECT * FROM activation WHERE pid = 'username';"
----

*Session Management:*
----
# Clear Redis sessions if using Redis for session storage:
redis-cli -p 6379 FLUSHALL

# Restart pfconfig to clear configuration cache:
/usr/local/pf/bin/pfcmd service pfconfig restart

[[pfconfig-connectivity-problems]]
==== Service communication errors with pfconfig

*Problem:* Services fail with "Can't connect to pfconfig on
containers-gateway.internal:44444" errors, particularly after system changes
or reboots.

*Solution:*

*Service Dependency Resolution:*

. *Check pfconfig Service Status:*
+
----
# Verify pfconfig is running:
/usr/local/pf/bin/pfcmd service pfconfig status

# If not running, start it:
/usr/local/pf/bin/pfcmd service pfconfig start
----

. *Hostname Resolution:*
+
----
# Verify containers-gateway.internal resolves:
nslookup containers-gateway.internal
ping containers-gateway.internal

# If resolution fails, check /etc/hosts:
echo "127.0.0.1 containers-gateway.internal" >> /etc/hosts
----

. *Network Configuration:*
+
----
# Check if pfconfig is listening on correct interface:
netstat -tlnp | grep :44444

# Verify firewall isn't blocking internal communication:
iptables -L | grep 44444
----

*Container Environment Issues:*
----
# If running in Docker/containers, verify network configuration:
docker network ls
docker exec -it packetfence-container ping containers-gateway.internal

# Check container network connectivity:
docker exec -it packetfence-container netstat -rn
----

*Service Restart Sequence:*
----
# Proper service restart order:
/usr/local/pf/bin/pfcmd service pfconfig stop
/usr/local/pf/bin/pfcmd service pfconfig start

# Wait for pfconfig to be ready:
sleep 5

# Restart dependent services:
/usr/local/pf/bin/pfcmd service pf restart
----

*Verification:*
----
# Test pfconfig connectivity:
/usr/local/pf/bin/pfcmd pfconfig get config.Configuration.general.hostname

# Check service logs for errors:
tail -f /usr/local/pf/logs/pfconfig.log
----
