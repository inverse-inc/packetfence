== Introduction

PacketFence is a fully supported, trusted, Free and Open Source network access
control (NAC) system. As with any complex network infrastructure component,
administrators encounter various challenges during installation, configuration,
and daily operations. This FAQ addresses the most common issues reported by
the PacketFence community, providing practical solutions and troubleshooting
guidance.

The questions and answers in this guide are organized by topic to help you
quickly locate information relevant to your specific deployment scenario.

== Installation & Compatibility

=== Operating System Compatibility

[[almalinux-compatibility]]
==== AlmaLinux 8 compatibility with PacketFence v13

*Problem:* PacketFence v13 installation or operation issues on AlmaLinux 8 systems.

*Symptoms:*

* Package dependency conflicts during installation
* Service startup failures after installation
* Database connection problems with MariaDB
* SELinux policy conflicts preventing proper operation
* Missing or incompatible system libraries

*Solution:*

*Pre-Installation Requirements:*

. *System Preparation:*
+
----
# Update system packages
dnf update -y

# Install required repositories
dnf install -y epel-release
dnf config-manager --set-enabled powertools
----

. *SELinux Configuration:*
+
----
# Check SELinux status
getenforce

# If needed, set to permissive mode temporarily
setenforce 0
sed -i 's/SELINUX=enforcing/SELINUX=permissive/' /etc/selinux/config
----

*PacketFence Installation on AlmaLinux 8:*

----
# Add PacketFence repository
curl -o /etc/yum.repos.d/packetfence.repo https://packetfence.org/downloads/PacketFence/RHEL8/packetfence.repo

# Install PacketFence
dnf install -y packetfence

# Configure MariaDB if needed
systemctl enable --now mariadb
mysql_secure_installation
----

*Post-Installation Configuration:*

----
# Start and enable PacketFence services
/usr/local/pf/bin/pfcmd service pf start

# Verify service status
/usr/local/pf/bin/pfcmd service pf status

# Check for any permission issues
/usr/local/pf/bin/pfcmd fixpermissions
----

*Troubleshooting Common Issues:*

----
# Check for dependency conflicts
dnf check

# Verify MariaDB configuration
systemctl status mariadb
mysql -u root -p -e "SELECT VERSION();"

# Check PacketFence logs for startup errors
tail -f /usr/local/pf/logs/packetfence.log
----

https://sourceforge.net/p/packetfence/mailman/message/58754773/[AlmaLinux 8 & PacketFence v13]

[[radius-audit-logs-empty-v14]]
==== RADIUS audit logs empty after upgrading to v14.0

*Problem:*
After upgrading to PacketFence 14.0, RADIUS audit logs show no entries despite active authentication attempts.

*Symptoms:*
* `radius_audit_log` table in database remains empty
* Reports → RADIUS Audit Log shows "No data available"
* Authentication appears successful in other logs (radiusd.log, packetfence.log)
* User devices authenticate and get network access normally
* Database queries show zero records: `SELECT COUNT(*) FROM radius_audit_log;`
* MySQL error logs may show timestamp-related warnings

*Solution:*

*Step 1: Fix Database Timestamp Issue*

----
ALTER TABLE radius_audit_log MODIFY created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP
----

*Step 2: Clear Redis Cache and Restart Services*

----
# Clear Redis cache on port 6379
redis-cli -p 6379
FLUSHALL
exit

# Clear Redis cache on port 6380
redis-cli -p 6380
FLUSHALL
exit

# Restart PacketFence services
/usr/local/pf/bin/pfcmd service pf restart
----

*Step 3: Verify Fix*

----
# Test authentication and check if logs appear
mysql -u root -p pf -e "SELECT COUNT(*) FROM radius_audit_log;"

# Monitor new entries in real-time
watch -n 5 'mysql -u root -p -e "SELECT COUNT(*) FROM pf.radius_audit_log;"'
----

[[ad-nt-error-codes-v14]]
==== Active Directory authentication fails with NT error codes

*Problem:* Authentication against Active Directory fails with specific NT
error codes after upgrading to v14.x.

*Symptoms:*

* Users cannot authenticate via 802.1X or captive portal
* RADIUS logs show NT error codes in authentication attempts
* Domain join appears successful but authentication fails
* Error messages in `/usr/local/pf/logs/packetfence.log`
* SSSD service may report connection issues
* `wbinfo -t` command may fail with trust relationship errors

*Common Error Codes:*

*NT Error 3221225762* ("Syntactically invalid computer name")::
Verify Active Directory FQDN configuration in domain settings. Ensure hostname
format matches AD requirements.

*NT Error 3221225506* ("Access denied")::
The account used for domain join lacks sufficient permissions to create machine
objects in Active Directory.

*Solution:*

. *For FQDN errors:* Check System Configuration → Domain Settings → DNS Name
. *For access errors:* Use account with "Create Computer Objects" permission
. *Verify domain join status:* Test with `wbinfo -t`
. *Check connectivity:* Ensure ports 389, 636, 88, 135 are accessible

*Community Reference:*
- https://sourceforge.net/p/packetfence/mailman/message/58829055/[NT Error 3221225762 on PacketFence v14 using AD]
- https://sourceforge.net/p/packetfence/mailman/message/58828744/[Active Directory error code 3221225506]

. *Configure RADIUS load balancer with session persistence*

Route all EAP authentication traffic to a single cluster node while distributing other traffic.

[[dns-cluster-failures]]
==== DNS resolution fails in cluster deployments

*Problem:*
DNS resolution problems in PacketFence cluster environments cause service failures and authentication issues.

*Symptoms:*
* DNS queries fail intermittently on cluster nodes
* Services can't resolve hostnames needed for operation
* External authentication sources become unreachable
* Captive portal redirects fail due to DNS issues
* Active Directory domain controllers can't be contacted
* Cluster node communication problems

*Solution:*

*Step 1: Check DNS Resolution on Each Node*

----
# Test DNS resolution on each cluster node
nslookup domain-controller.example.com
dig @8.8.8.8 domain-controller.example.com

# Test reverse DNS resolution
nslookup 192.168.1.10
----

*Step 2: Configure Consistent DNS Settings*

----
# Ensure all cluster nodes have identical DNS configuration
cat /etc/resolv.conf

# Update DNS settings on all nodes:
echo "nameserver 8.8.8.8" > /etc/resolv.conf
echo "nameserver 8.8.4.4" >> /etc/resolv.conf
echo "search example.com" >> /etc/resolv.conf
----

*Step 3: Verify Network Connectivity*

----
# Test connectivity to DNS servers from each node
ping 8.8.8.8
telnet 8.8.8.8 53

# Check for firewall blocking DNS
iptables -L | grep :53
----

*Cluster-Specific DNS Issues:*

----
# Check cluster VIP DNS resolution
nslookup cluster-vip.example.com

# Ensure all nodes can resolve cluster hostnames
for node in node1 node2 node3; do
  nslookup $node.example.com
done

# Test DNS from each interface
dig @192.168.1.1 example.com
----

*PacketFence DNS Configuration:*

----
# Update PacketFence DNS settings
grep -i dns /usr/local/pf/conf/pf.conf

# Restart networking services on all nodes
systemctl restart systemd-resolved
systemctl restart NetworkManager

# Restart PacketFence services after DNS fixes
/usr/local/pf/bin/pfcmd service pf restart
----

*Troubleshooting DNS in Cluster:*

----
# Monitor DNS queries in real-time
tcpdump -i any port 53

# Check DNS cache on each node
systemctl status systemd-resolved
resolvectl status

# Clear DNS cache if needed
resolvectl flush-caches
----

*Community Reference:*
https://sourceforge.net/p/packetfence/mailman/message/58767230/[DNS fails in cluster]

*Problem:* RADIUS SSL certificate is expiring and needs renewal without
service interruption.

*Solution:*

*Step-by-step renewal process:*

. *Navigate to PacketFence directory:*
+
----
cd /usr/local/pf

+
----

+
----
make conf/ssl/server.crt

. *Restart RADIUS service:*
+
----
/usr/local/pf/bin/pfcmd service radiusd restart
----

. *Verify certificate:*
+
----
openssl x509 -in conf/ssl/server.crt -text -noout | grep "Not After"
----

*Symptoms:*

. *Certificate Mapping:* Use `userPrincipalName` for computer objects if needed

*Example Configuration:*
----
# In authentication source settings
Username Attribute: servicePrincipalName
Search Filter: (&(objectClass=computer)(servicePrincipalName=host/*))

* Best for: Windows environments

== External Authentication Integration

=== SAML and OAuth Configuration

[[okta-saml-integration]]
==== Okta SAML integration configuration issues

*Problem:*
Cannot successfully configure Okta SAML authentication with PacketFence, users receive authentication errors.

*Symptoms:*
* SAML authentication redirects fail
* Users redirected to Okta but not returned to PacketFence
* "Invalid SAML Response" errors in logs
* Certificate validation failures
* Attribute mapping problems

*Solution:*

*Step 1: Configure Okta Application*

*Create SAML Application in Okta:*
* Application Type: Web Application
* SAML Version: 2.0
* Single Sign-On URL: `https://pf.domain.com/saml/sp/okta`
* Audience URI: `https://pf.domain.com/saml/sp/okta`

*Configure Attribute Mapping:*
* Username: `user.login`
* Email: `user.email`
* First Name: `user.firstName`
* Last Name: `user.lastName`

*PacketFence SAML Source Configuration:*

----
# Configuration → Authentication Sources → Add → SAML
# Source Name: okta
# IdP Entity ID: http://www.okta.com/[okta-id]
# IdP Single Sign-On URL: https://[org].okta.com/app/[app-id]/sso/saml
# IdP Single Logout URL: https://[org].okta.com/app/[app-id]/slo/saml
# IdP X.509 Certificate: [Copy from Okta]
----

*Certificate Configuration:*

----
# Ensure proper certificate format
# Download IdP certificate from Okta
# Configure SP certificate in PacketFence:
openssl req -new -x509 -days 3652 -nodes -out /usr/local/pf/conf/ssl/saml.crt \
    -keyout /usr/local/pf/conf/ssl/saml.key
----
